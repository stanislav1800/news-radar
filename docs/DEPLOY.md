# Развёртывание и эксплуатация

Всё, что нужно, чтобы поднять Сито у себя и обслуживать: запуск, команды, резервные копии, подключение
Telegram и LLM, настройки, выход в интернет. Обзор проекта — в [README](../README.md).

## Быстрый старт (Docker)

Нужен Docker с Compose и buildx (образ собирается BuildKit'ом).

```bash
# 1. Настройки: обязателен ключ SITO_SECRET_KEY
cp .env.example .env
python3 -c "import secrets; print(secrets.token_urlsafe(32))"   # вставить в .env как SITO_SECRET_KEY=...
#    и задайте свой пароль базы: POSTGRES_PASSWORD=... (в .env)

# 2. Запуск: база, миграции, веб и worker
docker compose up -d

# 3. Администратор (пароль спросит в консоли) и первые ленты
docker compose exec web sito user create admin --admin
docker compose exec web sito source add "ТАСС" https://tass.ru/rss/v2.xml
```

Откройте http://127.0.0.1:8000. Веб слушает только эту машину; открыть его в интернет — через обратный прокси, см. ниже. При первом запуске worker и веб скачают модель эмбеддингов (около 1,1 ГБ, том `models`), это несколько минут.

Обновление: `git pull && docker compose up -d --build` — миграции применятся сами (сервис `migrate`).

## Запуск из исходников (разработка)

Нужны Python 3.13, [uv](https://docs.astral.sh/uv/) и Docker для базы.

```bash
docker compose up -d db          # только база
cp .env.example .env             # DATABASE_URL (порт базы — см. compose) и SITO_SECRET_KEY
uv sync
uv run alembic upgrade head
uv run sito user create admin --admin
uv run python -m sito.worker     # в одном терминале
uv run sito web                  # в другом
```

## Команды

| Команда | Что делает |
| --- | --- |
| `sito web [--port 8080] [--reload]` | веб-интерфейс |
| `python -m sito.worker` | сбор и обработка; останавливается по Ctrl+C без потери данных |
| `sito user create <логин> [--admin]` | новый пользователь |
| `sito user list` / `sito user set-password <логин>` | список, смена пароля |
| `sito source add <название> <адрес> [--no-check]` | новая RSS-лента |
| `sito source list` / `enable` / `disable <id>` | источники |
| `sito pipeline recluster` | склеить все посты в сюжеты заново (после смены порогов склейки) |

Пользователями и источниками можно управлять и в вебе: раздел «Администрирование» в меню аккаунта (справа вверху) с вкладками «Состояние», «Источники» и «Пользователи». В «Состоянии» видно, жив ли worker, успевает ли конвейер, какие источники сломались или замолчали и какие посты застряли с ошибкой; если что-то не так, у меню аккаунта горит красная точка.

Для мониторинга и проверок контейнера есть `GET /health` (без входа): 200, если веб и база работают, 503 — если база недоступна; поле `worker` — работает ли worker.

## Резервные копии

Сервис `backup` раз в сутки делает копию базы в `./backups/sito-ГГГГММДД-ЧЧММ.dump` и хранит 7 последних (`BACKUP_KEEP` в `.env`). Если свежей копии нет больше 26 часов, администратор увидит уведомление (красная точка и сообщение в Telegram).

Восстановить (веб и worker на это время остановить, чтобы не писали в базу):

```bash
docker compose stop web worker
docker compose exec -T db pg_restore -U postgres -d sito --clean --if-exists < backups/sito-20261103-0400.dump
docker compose start web worker
```

Проверить, что копия читается, не трогая рабочую базу, — восстановить её в отдельную базу и удалить:

```bash
docker compose exec db createdb -U postgres sito_check
docker compose exec -T db pg_restore -U postgres -d sito_check < backups/sito-20261103-0400.dump
docker compose exec db psql -U postgres -d sito_check -c "select count(*) from post"
docker compose exec db dropdb -U postgres sito_check
```

Сессия Telegram и другие секреты в копии зашифрованы ключом `SITO_SECRET_KEY`: храните `.env` отдельно от копий, без него секреты не открыть. Папку `backups/` лучше регулярно уносить на другой диск или в облако — копия на том же диске не спасёт от его поломки.

## Telegram

Сито читает каналы через отдельный служебный аккаунт Telegram: посты приходят сразу, читаются и каналы без открытой веб-версии.

1. Заведите **отдельный аккаунт** (не личный: в личный приходят переписки, а при нарушении лимитов аккаунт могут ограничить). Лучше на настоящей SIM-карте и не совсем новый.
2. На [my.telegram.org](https://my.telegram.org) → API development tools получите `api_id` и `api_hash` этого аккаунта.
3. В Сито: меню аккаунта → «Администрирование» → «Источники» → «Добавить подключение: Telegram». Сразу после сохранения откроется вход. Проще всего — по QR-коду: в приложении Telegram этого аккаунта «Настройки → Устройства → Подключить устройство» и навести камеру. Можно и по коду (он приходит в приложение Telegram, не СМС). При двухэтапной проверке спросят облачный пароль (он не сохраняется).
4. Каналы — на странице «Каналы» у подключения (Администрирование → Источники → «Каналы →»):
   - **список подписок аккаунта** с переключателем «собирать / не собирать», поиском по списку и действиями над отмеченными, отписка прямо отсюда (посты остаются или удаляются — на выбор);
   - **добавить каналы**: вставьте ссылки (`t.me/имя`, `@имя`, приглашение `t.me/+…`, папку `t.me/addlist/…`, можно несколько) — Сито покажет каналы с числом подписчиков и последними постами, отмеченные аккаунт подпишет сам, по одному в минуту, и заберёт посты за сутки;
   - **настройки**: каналы, на которые подписались в приложении, собирать сразу или ждать решения; «тишина на телефоне» — каналы без звука, в архиве и прочитаны.

Сессия хранится в базе зашифрованной ключом `SITO_SECRET_KEY` и используется только worker'ом. Если её отзовут (Telegram → Настройки → Устройства), у подключения появится «нужен вход», а у меню — красная точка. Личные сообщения и группы не читаются, только каналы.

## LLM (необязательно)

Без LLM Сито работает полностью; с ней появляются пересказы, сводки и проверка тем. Подходит любой сервис
с API в формате OpenAI (routerai.ru, OpenRouter, DeepSeek, Ollama) — три строки в `.env`:

```
LLM_BASE_URL=https://routerai.ru/api/v1
LLM_API_KEY=...
LLM_MODEL=anthropic/claude-haiku-5.5
```

Что умеет — почти всё **только по кнопке**, в фоне без спроса ничего не тратится:

- **Пересказ сюжета** — кнопка на странице сюжета: заголовок и пересказ по полным текстам изданий, объём по материалу,
  где издания расходятся. Сохраняется; «Обновить», когда пришли новые посты. 0,03–0,2 ₽.
- **Сводка по теме** за день, неделю или месяц — вверху ленты темы: «Главное», разделы, «Что дальше», у каждого
  факта номер-ссылка на сюжет. Без новых сюжетов повторно не делается. 0,1–0,5 ₽.
- **Вопрос по теме** — поле там же: ответ только по сюжетам темы, со ссылками.
- **История** сводок и вопросов у каждой темы; **пожелания к сводкам** («пиши для руководителя, сначала цифры»)
  в настройках темы.
- **Дайджест по расписанию** — в настройках темы: каждый день, по будням или раз в неделю, во сколько, формат,
  «не делать, если новых сюжетов меньше N», свои пожелания. Читается в разделе «Дайджесты» (значок в шапке),
  вверху ленты темы и по RSS (`/rss/<секрет темы>/digests`). Время — по часовому поясу пользователя: он
  определяется по браузеру при первом заходе, дальше меняется только в настройках.
- **Тема по описанию** — «Описать своими словами» в поиске: модель предлагает название, запрос и описание,
  сразу виден предпросмотр; пустой или слишком широкий запрос она один раз поправляет сама. ~0,05 ₽.
- **Проверка по описанию** — включается в теме (фон): спорные новые сюжеты (слово мелькнуло в одном посте из многих,
  похожесть у порога) модель сверяет с описанием темы и убирает неподходящие; явные проходят без неё. Убранные видны
  в настройках темы, «Вернуть» делает сюжет примером. ~0,05 ₽ за пачку из 25.

- **Объединение недосклеенных сюжетов** — фон, для всех: склейка не соединяет посты с разрывом больше 6 часов
  (повторяющиеся «ограничения во Внукове» по тексту не отличить), поэтому новый сюжет, у которого рядом очень
  похожий более ранний (от 0,90, за 24 часа), модель сравнивает с ним: одно событие — сюжеты объединяются
  (посты, прочитанное, темы), разные — остаются «похожими». ~0,09 ₽ за 20 пар, около 7–8 ₽ в день;
  выключается `CLUSTER_MERGE_ENABLED=false`.

Расход: каждый запрос пишется в базу; в «Администрирование → Состояние» — запросы, токены и цена за сутки
и 30 дней. Лимиты за сутки — в рублях по цене сервиса (`LLM_DAILY_RUB`=150, `LLM_USER_DAILY_RUB`=50) и в токенах
(`LLM_DAILY_TOKENS`, `LLM_USER_DAILY_TOKENS`) для сервисов, которые цену не сообщают; кончился — кнопки отвечают
«лимит исчерпан», остальное работает. Объединение сюжетов — не больше `CLUSTER_MERGE_BATCHES_PER_HOUR`=12 пачек
в час (~1 ₽/ч даже после завала), сюжеты из догрузки старых постов не объединяет, каждое объединение пишется
в `story_merge_log`. Пока модель отвечает, соединение с базой свободно; при «перегружен» (429) и сбоях сервиса
запрос повторяется дважды с паузой; одно и то же (пересказ сюжета, сводка темы) одновременно не готовится дважды;
ответ, который оплачен, но не годится, по кругу не повторяется. «Размышление» моделей (DeepSeek V4, Claude Haiku 5.5)
выключено: для этих задач оно не нужно и съедает лимит ответа.

Сравнить модели на своём сюжете: `uv run sito llm summarize <id сюжета> --model deepseek/deepseek-v4.1-flash
--model anthropic/claude-haiku-5.5`. Замер 3.11.2026 на routerai.ru: качество близкое, Haiku по фактической цене
в 2–2,5 раза дешевле — она по умолчанию.

## Настройки

Все настройки — переменные окружения или строки в `.env`; полный список с комментариями в [src/sito/config.py](../src/sito/config.py), пример в [.env.example](../.env.example).

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `DATABASE_URL` | — | адрес базы |
| `SITO_SECRET_KEY` | — | подпись cookie сессий; без него веб не стартует |
| `WEB_HOST`, `WEB_PORT` | `127.0.0.1`, `8000` | где слушает веб |
| `SESSION_COOKIE_SECURE` | `false` | включить, если веб открыт через HTTPS |
| `FORWARDED_ALLOW_IPS` | `127.0.0.1` | каким прокси доверять заголовки `X-Forwarded-*` |
| `LOG_LEVEL`, `LOG_FORMAT` | `INFO`, `text` | логи; `json` — для Docker и сборщиков логов |
| `CLUSTER_*` | см. config.py | пороги склейки, подобраны по разметке в `eval/` |
| `POST_RETENTION_DAYS` | `90` | через сколько дней удалять тексты и векторы постов (сюжеты остаются) |
| `SOURCE_MAX_BACKOFF_HOURS` | `6` | самая длинная пауза перед опросом источника после ошибок подряд |
| `TOPIC_*` | см. config.py | пороги тем: с какого сходства 👍 добавляет и 👎 убирает сюжеты |
| `SEARCH_BY_MEANING` | `true` | загружать ли модель в веб для поиска по смыслу |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | — | LLM; без них кнопок LLM нет |
| `LLM_DAILY_TOKENS`, `LLM_USER_DAILY_TOKENS` | `3000000`, `1000000` | лимиты токенов LLM за сутки: всего и на пользователя |
| `LLM_*` | см. config.py | объём материала и потолки ответов |
| `FULL_TEXT_ENABLED` | `true` | скачивать полный текст статей RSS и статей по ссылкам из коротких постов Telegram |
| `FULL_TEXT_SHORT_POST_CHARS` | `500` | пост Telegram короче — фраза и ссылка: скачать статью по ссылке |
| `STORY_EXCERPT_CHARS` | `700` | сколько текста поста показывать в хронологии сюжета |

## Открыть в интернет

Сито само работает по обычному HTTP, как Grafana или Miniflux. HTTPS даёт обратный прокси перед ним. Как и где разворачивать, решаете вы; ниже два типовых варианта для прокси на той же машине.

**Caddy** (сам получает и продлевает сертификат Let's Encrypt):

```
sito.example.ru {
    reverse_proxy 127.0.0.1:8000
}
```

**nginx:**

```nginx
server {
    listen 443 ssl;
    server_name sito.example.ru;
    ssl_certificate     /etc/letsencrypt/live/sito.example.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/sito.example.ru/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;  # заменить, а не дописать: иначе адрес подделывается
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

И в `.env`:

```
SESSION_COOKIE_SECURE=true   # cookie сессии только по HTTPS
FORWARDED_ALLOW_IPS=127.0.0.1  # без Docker: адрес прокси; если прокси в другом контейнере — его адрес
```

`FORWARDED_ALLOW_IPS` важен: по заголовкам прокси Сито узнаёт настоящий адрес посетителя, а на нём держится ограничение попыток входа (после 5 неудач — пауза 5 минут). Доверять этим заголовкам можно только от своего прокси. В `compose.yaml` он задан как `*` (значение из `.env` там не действует): веб открыт только на `127.0.0.1`, и заголовок приходит лишь от прокси на этой машине. Поэтому прокси должен **заменять** `X-Forwarded-For` адресом посетителя (`$remote_addr`), а не дописывать к присланному им: иначе посетитель подставит любой адрес сам.

Что защищено в самом приложении при любом способе развёртывания: пароли хранятся как хэш argon2, cookie сессии `HttpOnly` и `SameSite=Lax`, формы защищены CSRF-токеном, после смены пароля прежние входы перестают действовать, страницы нельзя встроить в чужой сайт.
